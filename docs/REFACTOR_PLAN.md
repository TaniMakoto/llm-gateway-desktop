# 网关内核重构计划

开始日期：2026-10-11。保留单机桌面网关边界，核心为三协议转换、上游选择和故障转移。

跟踪议题：[架构重构 #22](https://github.com/TaniMakoto/llm-gateway-desktop/issues/22)。第一批随 0.2.0 提交；Rust 测试与安装包由 GitHub Actions 验证。后续批次仍是待实施工作。

## 必须保留的行为

- Chat、Responses、Messages 的九种客户端/上游组合，以及 JSON、SSE、工具调用和工具结果回放。
- 同协议保真；每个候选从客户端原始请求重新构建出站参数。
- 上游 HTTP 拒绝（包括 400）在输出提交前继续尝试可用候选；输出提交后不拼接其他供应商。
- 合法 token 截断、异常断流、工具不完整、客户端取消分别记录；未完成工具不能伪装为可执行的完整调用。
- 取消、换源、读流结束均释放容量；客户端取消不记为供应商健康失败。
- 旧配置和数据库可迁移，便携数据目录、托盘、启动偏好、请求诊断仍可使用。

## 第一批：可靠性边界和可独立测试的规则

1. 把终态判定和工具完整性规则抽成不依赖 Tauri/SQLite 的 Rust 库。
2. 让响应完整结束决定请求最终结果和健康记录，保留合法 usage 尾事件。
3. 引入尝试级资源对象，保证容量和半开探测许可在失败/取消时释放。
4. 配置版本、数据库事务和监听准备/发布，覆盖端口冲突、写入失败及并发保存。
   统一网关的候选、策略和重试预算从同一次读取的配置生成，避免保存期间混用旧路由与新供应商参数。
5. 按入口引用裁剪不可达命令、深链和无消费者同步服务；前端拆开类型、辅助函数和测试台。
6. 加入构建身份，整理行为文档与版权声明的打包引用。

验收以现有真实 HTTP 协议矩阵和新增异常回归为准。静态检查不替代 Rust 测试和 Windows 打包。

同协议直通保留上游响应字节，通过独立观察器识别不完整工具并修正请求结果、健康与诊断记录；跨协议转换在无法完成有效工具调用时输出失败终态。直通响应是否额外注入错误事件，留给后续明确的协议策略。

## 后续批次

- 逐步拆分候选规划、容量准入、上游执行与响应编码，移除内核对旧 CLI 应用域的依赖。
- 请求固定使用不可变配置快照，统一供应商、候选、公开别名和上游模型的身份类型。
- 将现有供应商兼容选项归并为明确配置；不引入静默字段丢弃或默认提示词改写。
- 继续裁剪失去引用的服务和依赖；保留历史 schema 迁移和有用的诊断数据。
- 扩展 reasoning、多模态、structured output、compact 与取消压力测试，按实际客户端需要验收。
- 明确完整停止/重新启动的排空时限和状态保留策略，覆盖仍有在途请求时的重启压力场景。

## 交付约定

完成本地可执行的检查后推送并触发 GitHub Actions。立即报告提交、工作流链接、本地验证及委托 CI 的检查，不等待或轮询编译结果。构建已触发不等于构建成功，也不等于本机已升级。
